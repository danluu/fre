# Requirement traceability

| Requirement | Required design response | Acceptance evidence |
|---|---|---|
| Rust implementation | Safe semantic/planning core; unsafe code isolated to ISA emitters, executable-memory runtime, and FFI | Workspace dependency audit, `cargo geiger`-style unsafe inventory, Miri/sanitizers where applicable |
| Same syntax/guarantees as Rust `regex` | Versioned Rust profile, Unicode and byte facades, exact leftmost-first/capture/empty-iteration behavior and API ledger; strict local validation covers non-resource behavior, while `size_limit` approximately caps FRE's charged persistent representation and does not promise the upstream threshold | Upstream Rust corpus, exhaustive and differential semantics tests, exact FRE resource-boundary tests |
| Same syntax/guarantees as RE2 | Separate complete RE2 syntax/encoding/option product, UTF-8/Latin-1 and operation wrappers; runtime `Set` OOM and other implementation-specific resource thresholds are not imitated by an FRE cap | Upstream RE2 tests and C++ compatibility harness for non-resource behavior |
| No worst-case blowup | Bounded parsing/planning/determinization/code generation; `O(PN)` universal single-search executor; operation-wide work ledger; exact aggregate-iteration theorem gate | Three-axis work-counter scaling and written proof per plan; final compatible iterator/product remains blocked rather than falling back quadratically if the gate fails |
| Faster than RE2 and Rust regex | Falsifiable semantics-matched per-case release gates on named hardware, not a claim based only on a geometric mean | All compatible Rebar cases, confidence intervals, lifecycle and missing-workload suite |
| All Rebar benchmarks | Treat all 68 definition TOMLs as the coverage universe; cover every accepted definition/engine-specific variant, including the 360-name current Rust-runner projection, seven models, 14 curated groups, and every top-level family | Pinned inventory, exact per-job runner/operation/timing manifest, FRE runner, per-definition audit, zero correctness exclusions without a documented syntax/semantic reason |
| Missing production uses | Changing inputs, one-shot/hot, fleets, streaming, ropes, replacement/split, lexers, binary/Unicode, concurrency, memory pressure, JIT-forbidden and cross-target use | Dedicated scenario matrix with performance, memory, and correctness results |
| Native JIT, not regex bytecode | Typed Kernel IR lowered by copy-and-patch/macroassembler backends; no opcode dispatch; large machines may use native loops over automaton data tables | Kernel-IR interpreter equivalence, disassembly checks, compile-latency/code-size/search bakeoff |
| SIMD | Concrete literal/set, fixed-window, class/UTF-8 and bit-state kernels on x86-64 and AArch64; no claim that arbitrary DFA dependencies disappear | ISA-specific microbenchmarks, guard-page tests, hardware counters and scalar equivalence |
| More optimizing AOT | Bounded high-fuel determinization/TDFA, state/tag/alphabet optimization, layout, multiversioning and optional PGO | Reproducible object artifacts, cross-target tests, AOT-versus-JIT/no-JIT measurements |
| Easy embedding like RE2 | Immutable compiled object, explicit/reusable scratch, stable versioned C ABI, RAII C++ wrapper, allocator/JIT callbacks, no global initialization | ABI compatibility suite, examples in C/C++/Rust, concurrency/no-JIT and single-threaded-fork/exec tests; no API after multithreaded POSIX fork before exec |
| Modular/testable internals | Syntax/HIR → semantic automata/reference → analysis/planner → Kernel IR → ISA/AOT; runtime and facade only depend downward | Layer-specific public test hooks, shared canonical match records, `fre-debug`, no semantic dependency on JIT/runtime |
| Retain reasonable alternatives | Candidate plans remain independently runnable; planner decisions are inspectable; disputed algorithms have preregistered bakeoffs | Round-review decision log and prototype gates |
| Requested persona process | 5 specialists + `Dan Luu` + 5 contrarians; every response receives two paired reviews twice; independent ultra runners, no subagents | `RUN_METHOD.md`, prompts, full logs and 11 + 22 + 22 reports |
