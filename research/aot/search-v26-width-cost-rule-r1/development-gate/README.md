# Search V26 fresh-disjoint development gate

This directory implements the result-blind gate frozen in
`../preregistration-v1.json`. It consumes only the independently generated V26
synthetic population. It does not read V25 result cells, Rebar, or LLVM output.

`gate-contract-v1.json` freezes the complete lattice, long-scan fixture
geometry, measurement orders, estimators, shard boundaries, and thresholds.
The source identity and cell-manifest hash deliberately remain `AWAITING`
until the coherent-relabel successor core and result-blind materializer are
reviewed. Timing authority must remain unavailable while either placeholder
exists.

The 7,776 cells are:

```
27 widths × 3 outputs × 16 accepted literals × 6 window shapes
```

Shards are equal and disjoint: widths 6–14, 15–23, and 24–32, with 2,592
cells each. Every long-scan fixture has a 2 MiB search window and is generated
one cell at a time. The first-legal-position fixture is intentionally only one
literal wide and measures call/setup overhead.

Implemented files:

- `runner/src/bin/materialize_cells.rs`: canonical result-blind cell manifest.
- `runner/src/bin/run_gate_shard.rs`: two-phase native/KIR preflight and
  timing runner.
- `runner/build.rs`: embedded source, toolchain, target, profile, and build
  identity.
- `analyze_v26_gate.py`: exact closure and frozen-threshold analyzer.
- `test_analyze_v26_gate.py`: synthetic analyzer tests only.
- `prepare_v26_gate_source.py`: controlled no-replace Git archive creation.
- `seal_v26_gate.py`: final immutable identity receipt creation.
- `launch_v26_gate_once.py`: fail-closed concurrent one-shot launcher.
- `test_seal_and_launch.py`: source, archive, publication, and launcher tests.

No command in this directory may launch timing until the seal has status
`SEALED_READY_FOR_ONE_SHOT_TIMING`, contains no placeholder, and authenticates the exact successor
source, runner binary, contract, cell manifest, and launcher bytes.

## Global semantic barrier

The one-shot launcher is deliberately two phase:

1. It creates the read-only run manifest and invokes three pinned
   `preflight` shards concurrently. Every shard independently reconstructs
   its 2,592 manifest records, emits and publishes V17 and V26 code, and
   compares portable, V17, and V26 outputs with the absolute-coordinate
   expected result. No clock is read and the one-shot authority is not
   consumed in this phase.
2. The launcher validates every record in all three immutable proof files.
   It then publishes one aggregate manifest binding all proof hashes, sizes,
   CPUs, nonces, source and executable identities. Only after that global
   7,776-cell barrier passes does it create-new the seal-keyed consumption
   marker.
3. Each timing shard independently authenticates the aggregate manifest,
   all three proof hashes and terminal records, and the consumption marker
   before reading the clock. A missing, late, replayed, or swapped proof is a
   hard failure.

This ordering ensures a semantic mismatch in a late cell cannot consume the
one permitted timing run after earlier cells have already been measured.

## Timing boundary

Programs, emitted images, published kernels, fixtures, haystack references,
`SearchWindow`, expected outputs, and execution limits are constructed
outside the measured interval. The interval contains only `N` calls through
the same native wrapper for V17 and V26, the minimum result `black_box`, and
the timer reads. There is no hashing, allocation, formatting, logging, or
multiply/rotate digest fold in the measured loop. The terminal result is
checked against the preflight-derived expectation after the closing timer
read.

Calibration begins at one call and doubles to at least 4 ms independently
for every cell and engine. The terminal and immediately preceding
calibration batches are retained. Twelve paired samples use every six-engine
order twice.

## Source and executable identity

Final sealing starts from one reviewed integrated Git commit and tree. The
controlled archive is made with absolute `/usr/bin/git`, replace objects
disabled, global/system attributes disabled, and an allowlisted environment.
The archive is regenerated byte-for-byte during verification, and its
embedded commit is checked.

The runner source-set V2 digest covers:

- every regular file below `crates/`, `synthetic-runner/`, and
  `development-gate/runner/`;
- root `Cargo.toml`, `rust-toolchain.toml`, and `.cargo/config.toml`;
- each Git-tracked executable bit, path, length, and byte sequence.

Selected symlinks or special files are rejected. The analyzer independently
derives the same digest from the archive and verifies the exact frozen
`preregistration-v1.json` hash. The release runner embeds commit, tree,
archive, source-set, Cargo/rustc, target/host triples, profile, optimization,
debug, feature, and build-configuration identities. Sealing requires an
ELF64 little-endian AArch64 runner containing exactly one matching marker,
`crt-static` in its target features, and no dynamic `PT_INTERP` loader.

The frozen Linux invocation uses the sealed absolute `/usr/bin/taskset`
binary. The launcher executes both taskset and runner through already
authenticated `/proc/self/fd` descriptors with only `LANG=C`, `LC_ALL=C`,
and `TZ=UTC` in the environment. Each runner verifies singleton CPU affinity
and hashes the live `/proc/self/exe` inode. The launcher never checks load,
waits for headroom or another GO, or stops other CPU work.

Child supervision is bounded and identity-safe. Every shard has a separate
inherited startup pipe, and all three children must be created and bound to
Linux pidfds before the launcher writes any readiness marker. A partial spawn
or pidfd failure closes every still-silent pipe and reaps the children without
granting authority, input access, or timer access. The analyzer has the same
single-child handshake. The sealed deadlines are two hours for preflight,
eight hours for timing, and two hours for analysis, versus a nominal
timing-shard duration of roughly 7–15 minutes. Processes finish naturally
until a deadline expires; escalation then sends `SIGTERM`, waits 30 seconds,
and sends `SIGKILL` only through the captured pidfds. There is no PID scan,
process-group kill, raw-PID signal, or unrelated-process target. A timing or
analyzer timeout occurs after the create-new consumption marker and therefore
leaves a terminal consumed attempt, never retry authority.

The artifact hashes do not turn the host into a hermetic operating system.
The Linux kernel, the Python runtime and standard library used by the sealed
launcher/analyzer, and the dynamic loader/libc used by sealed `taskset` are
explicit trusted platform inputs. The statically linked AArch64 runner still
independently checks its exact environment, singleton affinity, and live
executable inode. The analyzer is post-timing and may be rerun over the
immutable evidence if its first execution is interrupted.

The checked-in contract remains a result-blind draft. After the final
integrated source commit exists, the operator must:

1. create and review the controlled archive;
2. build the AArch64 release runner from that archive with the exact
   commit/tree/archive environment values;
3. materialize and independently validate the 7,776-cell manifest;
4. seal the immutable archive, runner, `/usr/bin/taskset`, launcher,
   analyzer, contract, and manifest;
5. publish the seal SHA-256 out of band before invoking the launcher.

Neither preflight nor timing reads Rebar or LLVM output.
